PaperDistill

Batch-convert scientific documents into structured, AI-ready Markdown

← All projects

PaperDistill is a desktop application. You point it at an input folder, a prompt file describing the structure you want extracted, and an output folder — it produces one Markdown file per document, using Anthropic, OpenAI, or a local Ollama model.

Since 0.1.2 it reads PDF, DOCX, XLSX, TXT and MD. Tick the formats you want next to the input folder; PDF alone is ticked by default, and the choice is remembered between runs.

It never invents content: extraction is driven entirely by your prompt and the text pulled from the document. The default instruction tells the model to work only from the provided text and to write Not found in PDF rather than guess.

Install on Windows

Windows will warn you, and the warning is expected. The installer is not code-signed, so SmartScreen shows a blue “Windows protected your PC” panel. Click More info, then Run anyway. If you would rather verify than trust, check the file's SHA-256 first — see below.
  1. Download PaperDistill-setup-0.1.2.exe.
  2. Run it. Get past SmartScreen as above.
  3. Accept the default installation directory and finish the installer. The default is inside your own user profile (%LOCALAPPDATA%\Programs\PaperDistill), which is why no admin rights are required. You may change it, but choosing a system-wide location such as C:\Program Files is the one way to make Windows demand an administrator.
  4. Launch PaperDistill from the Start menu.

To verify the download first, in PowerShell:

Get-FileHash .\PaperDistill-setup-0.1.2.exe -Algorithm SHA256

The result must match the line for that file in SHA256SUMS.txt.

Install on Linux

The AppImage is a single self-contained file — there is nothing to install, nothing to uninstall, and no sudo anywhere. Download it, make it executable, run it:

curl -O http://LIHW0056/release/PaperDistill-0.1.2.AppImage
chmod +x PaperDistill-0.1.2.AppImage
./PaperDistill-0.1.2.AppImage
If it fails with a FUSE error — dlopen(): error loading libfuse.so.2 — your distribution ships FUSE 3 and AppImages still want FUSE 2. Ubuntu 22.04 and later are the common case. Either install the compatibility library, or skip FUSE entirely: 
sudo apt install libfuse2          # option 1
./PaperDistill-0.1.2.AppImage --appimage-extract-and-run   # option 2, no root needed

To verify the download: sha256sum PaperDistill-0.1.2.AppImage and compare against SHA256SUMS.txt.

Build from source

Needs Node 20+. The repository is public, so there is nothing to request first. This is also the route for macOS.

git clone https://github.com/pvnazarov/PaperDistill.git
cd PaperDistill
npm install
npm run dev        # run it
npm test           # 67 tests
npm run package    # build an installer for the current platform into release/

Verified on Linux with Node 24 and Node 26, re-checked at 0.1.2 on 2026-08-21: dependencies install, all 67 tests pass, and npx electron-builder --linux produces the AppImage offered above. Note that npm run package builds for the platform you run it on — the Windows installer has to be built on Windows.

Set up a model

PaperDistill has no LLM of its own — you bring one. Pick a provider in the app:

ProviderWhat you need
AnthropicAn API key. Paste it into the app — it is held in memory for that session only and never written to disk. Model name, e.g. claude-sonnet-4-5.
OpenAIAn API key, pasted the same way. Model name, e.g. gpt-4o.
OllamaNothing — no key, no account. Run ollama serve locally, pull a model, and use Test Connection to check the default http://localhost:11434. Your documents never leave your machine this way.

If you would rather not paste a key each session, set it as a user environment variable before launching — ANTHROPIC_API_KEY or OPENAI_API_KEY. The app reads the environment it was launched with and never overrides a variable that is already set. On Windows, setx ANTHROPIC_API_KEY "your-key" in a terminal, then open a new one.

Using it

  1. Select an input folder, a prompt .txt file, and an output folder. Any of the three still unset is shown in red. Tick the file types to read — PDF, DOCX, XLSX, TXT, MD. Two prompts ship with the app and need no file picking: Use Papers Prompt for published papers, and Use Proposals Prompt for research/grant proposals — work packages, deliverables, planned cohorts, partners, and which methods were proposed for which data. Either is a working starting point to copy and edit.
  2. Choose a provider and model.
  3. Scan Files — extracts text from each one and flags likely scanned/image-only PDFs, plus any file that yields no text at all; those get skipped rather than sent to the model.
  4. Start. Pause, Resume, and Cancel work mid-run.

For each document you get <name>.md plus a <name>.paperdistill.json sidecar recording provider, model, page count and status, and one paperdistill_run_log.jsonl for the whole run. Existing .md files are never overwritten unless you ask.

Your prompt can use {{PDF_TEXT}}, {{PDF_FILENAME}}, {{PDF_PATH}} and {{PAGE_COUNT}}. They keep their PDF_ names so existing prompt files keep working, but they carry whichever document is being processed. If you use none of them, the extracted text is appended after your prompt — so plain English works fine. Only PDFs have pages, so {{PAGE_COUNT}} becomes unknown for the other formats.

Known limits

  • No OCR. Scanned or image-only PDFs are detected and skipped, not processed.
  • PDF text extraction uses pdfjs-dist, which can struggle with multi-column layouts, embedded tables, and unusual fonts.
  • DOCX is text-only — paragraph text is read; images, charts, comments, footnotes and tracked changes are not.
  • XLSX gives cell values, not spreadsheets — each sheet becomes tab-separated rows. Formulas are not evaluated (only their cached result is read), and styling, merged ranges, charts and images are ignored. Date-formatted cells are converted to YYYY-MM-DD. Legacy .xls is not supported.
  • One batch at a time — starting a second run while one is going is not supported from the UI.
  • Resume is filesystem-based: it checks whether <name>.md already exists, and does not track partial progress inside a single PDF.
  • Cloud-synced folders (OneDrive, Dropbox) can cause EBUSY errors during builds — work from a local path.
